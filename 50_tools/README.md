# 50_tools — 検証・解析ツール

実機検証とログ/画像解析に使うスクリプト置き場。**アプリのビルドには一切関与しない**。

ログ実体(`_retrieved_logs/`)と画像(`_picture/`)は容量が大きいためリポジトリでは追跡していない。
解析スクリプトはスクリプト自身の位置から相対でこれらを参照する(`__file__` 基準)ので、
リポジトリを別の場所へ置いても動く。

## analysis — ログ/画像の解析

| ファイル | 用途 |
|---|---|
| `an_run_0722.py` | 通し撮影ログの解析。2台分のSHOTが交錯するログを**フレーム番号で2ストリームに分離**し、露出軌跡と撮影周期を出す |
| `an_timing_0722.py` | `prep`(準備)の内訳 `rdy`(測光)/`set`(露出設定) をカメラ別に比較。周期が崩れる原因の切り分け用 |
| `an_overnight_0720.py` | 同上(2026-07-20版。露出暴走を発見したときのもの) |
| `an_img_linear.py` | CR3の埋め込みJPEGから輝度ヒストグラム→**中央値・リニア輝度・飽和率**。露出が適正かを画像で判定する |
| `check_regression.py` | 回帰確認 |
| `cr3_read.py` | CR3 から EXIF(ISO/ss/F/時刻)と埋め込みプレビューJPEGを取り出す**モジュール**。exiftool 不要。CR3 は箱(CMT1/CMT2)を名指しして読むこと — TIFFヘッダの総当たりだと Canon メーカーノートを掴んで嘘の値になる |
| `check_no_japanese.py` | Entity と通信路に日本語リテラルが混ざっていないかを数える(コメントは対象外)。**0件が正**。方針は commit f6a4e8d |

**ストリーム分離の注意**: フレーム番号の貪欲2分割で行っている。**必ず撮影結果レポートのコマ数と
突き合わせて分離の正しさを検証すること**(過去にラベルが逆になっていたことがある)。

## edge — エッジ端末(M5Stack CoreS3 / M5StickS3)

| ファイル | 用途 |
|---|---|
| `mon_edges.py` | 両機のシリアルを同時に常時監視。各行に壁時計を付け、**リセット/パニックのマーカーを検出**。`mon_stop.flag` で停止 |
| `edge_dumplog.py` | シリアル経由で当日ログを吸い出す(`python edge_dumplog.py COM4 out.log`)。**CoreS3のみ。StickS3には`l`コマンドが無い** |
| `edge_info_both.py` | 両機に `i` を投げて state/wifi/IP を確認 |
| `edge_batt_probe.py` | 両機に `b` を投げてバッテリ(pct/volt/chg)を確認 |
| `edge_reset.py` / `edge_serial*.py` / `diag_stick.py` ほか | 個別の診断 |

**接続でリセットさせないため、シリアルは必ず `dtr=False, rts=False` で開くこと。**

## camera — カメラ探索・CCAPI

| ファイル | 用途 |
|---|---|
| `find_cams_http.py` | サブネットをCCAPI(8080)で総当りし機種/シリアルまで特定する。**探索はこれを正とする** |
| `find_cams_ssdp.py` | SSDP探索。複数NIC環境では送信元IPの指定が必須 |

**SSDPの無応答をカメラ不在の根拠にしないこと。** スマホ直結後にカメラがSSDP広告を止める既知現象がある。
また ping 不通も根拠にならない(ICMPを返さない場合がある)。過去に雑なポートスキャン
(254本同時・700ms待ち)で稼働中のカメラを取りこぼし、「オフライン」と誤断定した。

## Wi-Fi / BLE 共存の実測(2026-08-14)

BLE中央役の負荷装置は `40_src/20_HolyGrailEntity/80_test/10_M5Stack/025_ble_load`(独立スケッチ。
製品コードは使わない)。**PCにBluetoothアダプタが無い**ため、予備のCoreS3を中央役に仕立てている。
撮影中のエッジへ BLE 接続し、GATT read を連続で投げる。シリアル `c`=負荷開始 / `x`=停止。

結果(StickS3+R100 / 15秒周期 / 各60コマ / 接続間隔15ms・21アクセス毎秒):

| | BLE無し | BLE接続中 |
|---|---|---|
| 実周期 | 14.99993秒 | 15.00000秒 |
| 遅れたコマ / late最大 | 0 / 0ms | 0 / 0ms |
| 測光失敗 | 0 | 0 |
| prep 平均/最大 | 1713/2592ms | 1737/2542ms |
| busy 平均/最大 | 1866/2764ms | 1895/2596ms |

**判定に効く指標に差は出なかった。**平均の +1.4〜1.6% は朝の明るさ変化と区別できず、最大値は
むしろ改善している。BLE アドバタイズのみの状態は以前から常時稼働しており無害と実証済み。
