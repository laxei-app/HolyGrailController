# 2026.09.01 preNight(夜間前移行)の輝度変動

2026-09-01 夕方の通し(R10・スマホ直結)の実画像から、preNight 区間のコマ間の
明るさの安定性を調べた記録。**結論: 安定していない。約0.45段のノコギリが周期2分強で出る。**

引き続き測定して総合判断するため、測り方と数値をそのまま残す。

---

## 1. 対象

| | |
|---|---|
| 計画 | シグモイド phono R10 夕（夕日撮影は入れていない） |
| 撮影 | 2026-09-01 16:30〜20:30 / EOS R10 / スマホ直結 / 15秒周期 / 960コマ |
| 画像 | `_picture/2026.09.01(夕)/R10 シグモイド/IMG_0001〜0960.CR3` |
| ログ | `_retrieved_logs/hg_2026-09-01.log.txt` |
| 場所 | 自宅 36.0514,139.4268（窓越し・空が画面の6割ほど） |

窓の割り当て（ログの PLAN 行）

```
Daylight    16:30 〜 18:09
preNight    18:09 〜 19:10      ← 調査対象
Nightscape  19:10 〜 20:29      固定 1600/8/1.4
```

夜間の固定露出はユーザー設定なので今回の評価対象外。

---

## 2. 測り方

CR3 の埋め込み全画素JPEG(6000x4000)を PIL の `draft` で 1/4 に落として輝度(L)を取り、
256bin ヒストグラムから

* **中央値** … `histMedian` と同じ手順（アプリの測光と同じ土俵）→ sRGB伝達関数を外してリニア化
* **平均** … 各binをリニア化してから加重平均（画面全体のリニア輝度）
* **飽和率** … sRGB 250以上の画素の割合

を出し、EXIF の ISO/ss/F と撮影時刻でログの SHOT 行に突き合わせた（960コマ中959コマ一致）。

**注意: センサーRAWではなくカメラ現像後のJPEG**。ピクチャースタイルのトーンカーブが残るので、
露出1目盛りに対して画像は **1.28倍** に増幅されて見える（実測、n=24、0.89〜1.86倍）。
段数を語るときはこの倍率で割ること。真のセンサーリニアが要るなら rawpy を入れる。

被写体側の明るさ（露出を外した相対値）は

```
scene[段] = log2(Y) + log2(F^2 / ss) - log2(ISO/100)
```

飽和すると嘘の値になるので、飽和率2%以上のコマは除外して評価した。

| **preNight 前半 18:09〜18:35** | **0.153段** | 0.190 | +0.43 / −0.19段 |

**preNight は日中の 2.7倍 ぶれている。**

### 3.2 形はノコギリ

222コマを「露出が動いたコマ」と「動かないコマ」で分けるときれいに分かれる。

* 露出が動いたコマ（19回）… **+0.434段の跳ね上がり**（+0.38〜+0.56段）
* 露出そのままのコマ（198回）… **−0.057段/コマ でずり落ち**

### 3.3 測光方式の切替で山の形が変わる

18:34:50（fr=500）で測光が **ライブビュー → 実写サムネイル + 4コマ間引き** へ切り替わる。

| 測光方式 | 山の本数 | 1山の長さ | 山の落差 |
|---|---|---|---|
| LV（毎コマ） | 19本 | 5.6コマ = 84秒 | 平均 0.50段 |
| サムネイル（4コマ間引き） | 6本 | 19.5コマ = 292秒 | 平均 0.28段 |

後半の落差が小さいのは制御が良くなったからではなく、**18:45頃に空が暗くならなくなった**ため
（下記 3.5）。

### 3.4 露出の狙い(ev0)には乗っている

SHOT 行の `ev` は 18% 基準なので −2段 と出るが、preNight の狙いは 18% ではない。
`exposureMath.h` の ev0 シグモイドが太陽高度に応じて目標を 0.18 → 0.06 へ下げる（`linearLo=0.06`）。
狙い値を計算して測光値と並べると、追従そのものは **−0.56 〜 +0.29段** に収まっている。

| 時刻 | 太陽高度 | ISO/ss | 測光Y | 狙いev0 | 差 |
|---|---|---|---|---|---|
| 18:10 | −0.8° | 100 / 1/15 | 0.164 | 0.179 | −0.12段 |
| 18:25 | −3.7° | 100 / 0.3s | 0.087 | 0.115 | −0.39段 |
| 18:35 | −5.7° | 100 / 3.2s | 0.056 | 0.061 | −0.11段 |
| 18:45 | −7.6° | 100 / 8s | 0.041 | 0.060 | −0.56段 |
| 18:55 | −9.5° | 160 / 8s | 0.066 | 0.060 | +0.14段 |
| 19:05 | −11.5° | 160 / 8s | 0.074 | 0.060 | +0.29段 |

狙いが 0.06 に張り付く（高度 −5.7°以降）ので、**画像が暗くなること自体は設計どおり**。
問題は平均のずれではなく **コマ間のばらつき**。

いちばん外れた 18:40〜18:50 は、ss が暗所限界 8秒に達して ISO へバトンタッチする所。
ISO 100→125 が入るまで4分かかっている。

### 3.5 参考: 空自体の明るさ

露出を外した相対値（飽和2%未満のコマのみ、中央値ベース）。

| 区間 | 変化 |
|---|---|
| 16:57〜18:09（日中） | −4.5段 / 72分 = −0.06段/分 |
| 18:09〜18:45（preNight前半） | −9.5段 / 36分 = **−0.26段/分** |
| 18:45以降 | **ほぼ横ばい**（−4.17 → −4.00 段、むしろ微増） |

18:45（高度 −7.6°）でこの場所の空は暗くならなくなる。光害の底と思われる。
**別の場所で測ると前半の落ち方も後半の平坦さも変わるはず**なので、次回は場所も記録すること。

## 4. 原因（ログで裏が取れた分）

4つが積み重なっている。

1. **露出の刻みが1/3段** — 実際のss梯子は 0.26〜0.42段。ノコギリの高さの下限を決める。
2. **デッドバンド 0.3段** — 0.3段ずれるまで動かさない。必ず「0.3段ずり落ちてから0.33段跳ねる」
   になる。振動止めに入れた帯（[[exposure-oscillation-deadband]] 43cd37d）が、そのまま
   ノコギリの振幅を決めている。
3. **4コマ間引き** — 18:34:50以降、測光は60秒に1回。補正の上限が 0.33段/分 になる。
   空が 0.26段/分 で落ちている前半では余裕がほとんど無い。
4. **移動平均3サンプル** — 間引き後は3分ぶんの平均になり、実質1.5分の遅れ。

**最悪の山（−1.28段）の直接原因は 4。** ログの生の測光値と移動平均を突き合わせると:

| 測光コマ | 生Y | 狙いev0 | 生の誤差 | 移動平均3の誤差 | 動作 |
|---|---|---|---|---|---|
| fr=500 (18:34:50) | 0.0561 | 0.0607 | −0.11段 | −0.11段 | 帯の中・据え置き |
| fr=504 (18:35:49) | 0.0576 | 0.0607 | −0.08段 | −0.10段 | 据え置き |
| fr=508 (18:36:49) | 0.0427 | 0.0607 | **−0.51段** | −0.22段 | **帯の中と判定・据え置き** |
| fr=512 (18:37:50) | 0.0328 | 0.0607 | −0.89段 | −0.45段 | ここで初めて1目盛り |

fr=508 の時点で生の値は 0.51段 外れていたのに、移動平均では 0.22段 に薄まってデッドバンドの
中に入り、1分間見送られている。

### 未対処（案。まだ手を入れていない）

* デッドバンドを1目盛りの半分（0.17段）にして「ずり落ち0.3段→跳ね0.33段」を「±0.17段」に寄せる
* 間引き時は移動平均の本数を減らす、または時間で重み付けする（サンプル数でなく経過時間で平均）
* 空の落ち方が速い区間だけ間引きを止める

いずれも振幅と遅れのトレードオフなので、**別の日・別の場所の測定を足してから決める**。

## 5. 次回に見ること

* 光害の少ない場所で、空が最後まで落ち続ける条件のノコギリ振幅
* postNight（朝）でも同じ形が出るか（測光の切替が逆順になる）
* 曇天/晴天の差（空が均一だと中央値が安定するはず）
* ss が暗所限界に達して ISO へ移る所の遅れ（今回4分）
* デッドバンドや移動平均を変えた場合の前後比較

比較できるよう、**測り方（2章）は変えないこと**。トーンカーブの1.28倍も機種で変わるので、
機種を変えたら測り直す。
