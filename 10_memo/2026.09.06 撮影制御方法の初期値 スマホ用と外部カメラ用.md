# 撮影制御方法の初期値 — スマホ用と外部カメラ用（2026-09-06 仕様・実装）

## 決まり（ユーザー指示）

- 初期値（プリセット）は **外部カメラ用**（出荷時のコード生成。Nightscape / Sunrise / Sunset / Daylight）と
  **スマホ用**（夜間スマホ / 朝日スマホ / 夕日スマホ / 日中スマホ）の 2 組を用意する。
- 各初期値は「スマホ向け」の印（`forPhone`）を持ち、エディタの刻みと範囲が切り替わる。
  - on : 1/12 段、ss 48〜1/50000、F1.5〜3.5、ISO20〜12800（数値から生成）
  - off: 1/3 段、ss 30〜1/16000、F0.5〜24、ISO100〜24000（慣用の表記を範囲で絞る。1/6 段の余裕）
- 初期値はユーザーが触らない限り変えない。計画・ひな形は取り込むときに自分のカメラの目盛りへ寄せる。
- 名称は UI から渡す（将来の言語対応を UI だけで済ませる）。

## スマホ用の値（内蔵カメラのうち焦点距離が最短のもの＝Pixel 6 超広角 16mm から）

| 型 | 暗所限界 | 明所限界 | その他 |
|---|---|---|---|
| 夜間 | ss=NPF 未満の最大の目盛り（48 秒まで） / F=最小 / ISO=1600 に最寄り | 同左（固定露出） | |
| 朝日・夕日 | 夜間の値（基準も同じ） | ISO100 に最寄り / 1/16000（カメラがそこまで速くなければ最速） / 最大 F | 順 iso→ss→F、ev -3.0、ヒステリシス 0.5ev、移動平均 3 |
| 日中 | 朝日と同じ | 朝日と同じ | ev 0.0 |

- 4 種とも「優先的な初期値にする」。新規計画はこれを取り込み、カメラの目盛りへ寄せる
  （EOS R10 なら 48 秒→30 秒、ISO1632→1600）。取り込んだ ss で最小周期を割れば周期を伸ばす。
- 実測（Pixel 6）: 超広角 16mm = 夜間 48 秒 / ISO1632 / F2.2、明所 ISO102 / 1/16084 / F2.2。

## 撮影計画ひな形（内蔵カメラごと）

- カメラ・レンズは内蔵のもの。撮影制御方法は上と同じ規則を**そのカメラの実力**で組み立てる
  （NPF・並びがカメラごとに違う。広角 24mm は夜間 19.7 秒 / ISO1580 / F1.9）。
- 周期は 30 秒と最小周期（最長 ss×1.25）の大きいほう（超広角は 48 秒 → 60 秒）。窓は今日 20:00〜翌 04:00。
- 作るのは内蔵カメラの登録時（`builtinRegister.cpp`）の一度だけ。出荷時設定に戻せば作り直す。

## 実装の所在

- `hgc::ccmBase::forPhone`（JSON `forPhone`）、`expo::presetValues(kind, forPhone)`、`hge_getPresetExpoValuesJson`。
- `MainActivity`: 初期値エディタは `forPhone` で目盛りを切り替え（`expoListsMode`）、「スマホ向け」チェックは印だけ保存して開き直す
  （未保存の編集があればそれも保存）。離脱時の保存は変更があったときだけ。
- `builtinRegister.cpp`: `makePhonePresets` / `makeTemplate`（`buildPhoneSet` が共通の規則）。名前は `nativeRegisterBuiltinCameras(namesJson)`。
- `clampExposureToGear`: 範囲外の丸めに加えて目盛りに無い値を最寄りへ吸着（計画・ひな形・カメラ/レンズ変更の全経路）。
