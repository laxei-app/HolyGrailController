■構造見直し caude の質問
① etpEdge.cpp の RTC 分岐 ← これが本命の「機種による分岐」

void initExternalRtc(void)
{
    if (M5.Rtc.isEnabled()) { return; }   // 内蔵RTCがあるなら使う(CoreS3)
    M5.Ex_I2C.begin();
    g_extRtcOk = g_extRtc.begin(&M5.Ex_I2C);   // 外付けを探す(StickS3)
}
bool rtcOk(void) { return M5.Rtc.isEnabled() || g_extRtcOk; }

CoreS3＝内蔵RTC、StickS3＝外付けRTC という機種差を、実行時に M5.Rtc.isEnabled() で判定しています。ご指摘の「間接的に機種によって分岐するところ」に該当します。

② edgeProv.cpp の #ifdef EDGE_NIMBLE2 ← これは機種分岐ではありません

# 両ターゲットとも同じ
-D EDGE_NIMBLE2   ; NimBLE-Arduino 2.x のAPI差分
lib_deps: h2zero/NimBLE-Arduino@^2.2.3   # 両方 2.x

両機とも同じ値を定義しており、これは「ライブラリのバージョン差」の分岐です。旧 NimBLE 1.4 時代の名残で、現在はどちらも 2.x なので分岐自体が死んでいます（#ifdef の else 側は到達しない）。

A案が指示に沿いますが、確認させてください。 実は M5.Rtc.isEnabled() による判定は、「CoreS3 かどうか」ではなく「内蔵RTCが在るか」を見ています。つまり 機種 ではなく ハードウェア構成 の判定です。StickS3 に外付けRTCを付けなければ両方 false になり、CoreS3 でも故障すれば false になります。

この見方だと B案（現状維持）も筋が通ります。一方で「StickS3 は外付けを探す」という前提が共通コードに埋まっているのは事実で、そこはA案で解消できます。

あわせて、edgeProv.cpp の死んだ #ifdef EDGE_NIMBLE2 は削除してよいでしょうか（両機とも 2.x なので分岐が不要）。これは純粋な整理です。
