# tm0（測光＋露出設定）処理時間の計測

計測日: 2026-07-02（日中撮影）
対象カメラ: Canon EOS R10 @ 192.168.1.10
撮影周期: 15秒

## 目的・背景

撮影1コマごとに走る **tm0 = 測光(rdy) + 露出設定(set) の合計処理時間** を、
「撮影主体（スマホ直 / エッジ端末）」×「シーンの明るさ（通常 / 真っ暗 / 白飛び）」の
組み合わせで実測し、処理時間が何に支配されるかを切り分ける。

露出（明るさ）は撮影制御方法(ccm)の **日中(day)** の限界値を書き換えて作った：

- **真っ暗**: 暗所限界＝明所限界に揃える（ISO100 / SS1/4000 / f16）→ 最小露出固定
- **白飛び**: 明所限界＝暗所限界に揃える（ISO51200 / SS1/4000 / f1.4）→ 最大露出固定

### 用語（SHOTログのフィールド）

```
tm0=Nms off=Nms rdy=Nms(OK/NG) set=Nms(OK/NG) sh=HH:MM:SS.mmm
```

- **tm0**: 測光＋露出設定の合計処理時間（本計測の主対象）
- **rdy**: 測光。ヒストグラム(輝度)をHTTPで取得し露出計算する処理
- **set**: 露出設定。算出した ISO/SS/F をカメラにPUTする処理
- **off**: シャッターのオフセット時間 = (周期 − maxSs) × 0.7。
  maxSs は全ccm中の最大SS＝**夜の8秒**で固定なので、day計画でも off=(15−8)×0.7=**4899ms** になる（day のSSと無関係）
- **sh**: シャッターを実際に切った時刻（周期精度の評価用）

### 各Runの詳細

**Run1（エッジ・通常）**: tm0中央値 2568ms。off(4899ms)超過は1回のみ(4920ms)。

**Run2（スマホ・真っ暗）**:
- rdy(測光) 中央値444ms / 最大2336ms → tm0のほぼ全部が測光
- set(露出設定) 中央値0ms / 最大71ms → 露出が限界同値で固定のため設定はほぼ即時
- sh時刻ジッタ 最大2ms・平均絶対0.5ms → タイマ精度は極めて良好

**Run3（エッジ・真っ暗）**:
- 暗いプランはスマホからエッジへ正しく転送された（frame1 = ISO100 / 1/4000 / f16, Y0.0003）
- rdy(測光) 中央値1503ms / 最大2875ms、測光NG(失敗)14回/111 → エッジのヒストグラム取得(HTTP+処理)が重い
- 固定露出でも rdy が支配的で tm0 は縮まらない。tm0中央値2177ms ≒ Run1(2568ms)
- sh時刻ジッタ 最大1ms・平均絶対0.0ms → エッジのタイマ精度も極めて良好

**Run4（スマホ・白飛び）**:
- 白ccm(明所=暗所=ISO51200 / 1〜4000 / f1.4)を正しく適用。Y=1.004(完全白飛び), ev+2.48
- rdy(測光) 中央値993ms / 最大3161ms → tm0のほぼ全部。set≈0
- sh時刻ジッタ 最大2ms・平均絶対0.3ms → 良好。off超過なし

**Run5（エッジ・白飛び）**: 当初はエッジ開始が空振りしてブロックされていたが、エッジ再フラッシュ(再起動)＋アプリ再インストール後に開始成功。47フレーム取得。
白ccm(明所=暗所=ISO51200 / 1/4000 / f1.4)を正しく適用、Y≈1.001(完全白飛び)、ev+2.48。
tm0 中央値2149ms / 平均2150ms(208〜4916ms)。off(4899)超過2回。
**予測どおりエッジtm0はシーン非依存で ~2.1〜2.6s に収まった**（通常2568 / 真っ暗2177 / 白飛び2149）。

（当初のブロック要因＝スマホ→エッジ開始が効かなかった件は「エッジ端末が動かない原因調査」を参照。開始不発は再起動で解消し、コード経路自体は健全と判明した。）

## 考察・結論

1. **エッジのtm0はシーンの明るさにほぼ非依存** — 通常2568ms / 真っ暗2177ms / 白飛び2149ms。
   測光(rdy=ヒストグラムのHTTP取得＋処理)が支配的で 1.5〜2秒で固定。露出を固定しても縮まらない。

2. **スマホのtm0はシーンにやや依存** — 真っ暗469ms ↔ 白飛び1018ms。
   測光対象の明るさで測光処理の重さが変わる。

3. **エッジはスマホの約2.6〜4.6倍遅い** — 測光HTTPの往復＋端末上の処理コストが主因。
   （スマホ真っ暗469ms に対しエッジ真っ暗2177ms ＝ 約4.6倍）

4. **タイマ精度(sh時刻ジッタ)は全Runで極めて良好＝1〜2ms** —
   露出制御の重さと無関係にシャッター投下時刻は安定している。

5. **off超過** — off=4899ms（=(15−8)×0.7、maxSs=夜8s固定）に対し、
   超過はRun1で1回のみ、他は0。tm0はoffに十分収まっている。

### 示唆

- エッジ運用でも撮影タイミング(周期精度)は問題ない。
- ボトルネックは測光(ヒストグラムHTTP取得)であり、露出設定やタイマではない。
  高速化の余地があるとすれば測光の取得方法・頻度。
- 周期を詰める場合、エッジは tm0 ~2.6s + off 分の余裕が要る点に注意。
